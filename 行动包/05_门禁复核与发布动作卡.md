# 动作卡 5｜切换门禁重算与发布复核

**负责角色**：安全负责人（确认审查已签）+ 独立审批人（批准切换）
**预计耗时**：15–30 分钟
**产出的证据**：`artifacts/acceptance/CUTOVER_GATE_RESULT.json`
**门禁角色**：第 5 项阻塞；只有真人安全审查通过后才能由签署人把 `securityReviewPassed` 置 true。

## 1. 前置条件

- 动作 3 的 `HUMAN_SECURITY_REVIEW.json` 已签署（`humanReviewSigned=true`）；
- 动作 4 的 `APPROVALS.json` 已四方签署；
- CI 与 staging 证据在 30 天有效期内。

## 2. 更新切换证据

在 `artifacts/step22/cutover-evidence.json`（或发布专用副本）中补齐：

```json
{
  "securityReviewPassed": true,
  "approvedBy": "<独立审批人姓名>",
  "reportPath": "<本次发布证据包路径或编号>"
}
```

> `securityReviewPassed=true` 只能由安全审查签署人操作，且必须与 `HUMAN_SECURITY_REVIEW.json` 的签署一致。

## 3. 重算切换门禁

```bash
node scripts/migration-cutover-gate.js --evidence artifacts/step22/cutover-evidence.json | tee artifacts/acceptance/CUTOVER_GATE_RESULT.json
```

期望：

```json
{ "eligible": true, "decision": "ELIGIBLE_FOR_MANUAL_APPROVAL", "blockers": [] }
```

若仍 `BLOCKED`，按 `blockers` 逐条补齐（测试/真实 PG/备份/恢复演练/停写确认/回滚/安全审查）。

## 4. 统一门禁复核

```bash
npm run gate:acceptance          # 期望 READY_FOR_MANUAL_FINAL_REVIEW
npm run action:next              # 应提示"全部外部证据已齐"
npm run preacceptance:check      # 应 localChecksPass=true；退出码 2 表示仍有阻塞，按提示处理
npm run checksums:verify         # 142+ 文件校验
```

## 5. 人工最终复核清单（发布前 10 分钟）

- [ ] 打开 CI run URL，确认 commit 与发布 commit 一致；
- [ ] 打开 staging 证据，确认 `kind=staging`、执行人、时间、对账零差异；
- [ ] 打开安全审查文件，确认签署人、范围、整改项；
- [ ] 打开审批文件，确认 4 个不同签署人、无自批；
- [ ] 确认发布包 SHA256 与审批记录中一致；
- [ ] 确认回滚方案、观察期、告警阈值、事故联系人；
- [ ] 独立审批人给出最终 go/no-go。

## 6. 发布与回滚触发

- 发布：按运维变更单执行；发布后观察 `/readyz`、错误率、P95 延迟、数据库连接池。
- 回滚触发（示例，按团队标准调整）：`/readyz` 连续 5 分钟 503；错误率 > 1%；P95 延迟翻倍；数据校验异常。
- 回滚：切回 `DATABASE_BACKEND=sqlite`（技术演练已验证）或恢复上一版本；回滚后必须重新对账并记录。

## 7. 发布后归档

- 把本次全部证据（CI、staging、安全审查、签署、门禁结果、发布记录）归档到发布证据库；
- 更新 `MEMORY`/运维记录中的已知限制与遗留整改项；
- 关闭整改跟踪项时需附证据，不得口头关闭。
