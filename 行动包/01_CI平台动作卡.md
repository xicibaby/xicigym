# 动作卡 1｜真实 CI 平台记录

**负责角色**：研发（具仓库推送权限）
**预计耗时**：20–40 分钟（含 CI 等待）
**产出的证据**：`artifacts/ci/CI_PLATFORM_RECORD.json`
**门禁角色**：第 1 项阻塞；本地等价执行不能替代。

## 1. 前置检查（2 分钟）

```bash
npm run evidence:ci-local      # 期望 ALL CHECKS PASSED (ciPlatformRecord=false)
npm test                       # 期望 128 通过、0 跳过
```

`ci.yml` 已加固：`permissions: contents: read`、`npm ci`、setup-node 缓存、产物上传、并发去重、PostgreSQL 16 服务带 `pg_isready` 健康检查。

## 2. 推送仓库

若还没有仓库（在项目根目录执行；本机若无 git，先安装 Git for Windows 或使用 GitHub Desktop 拖拽上传）：

```bash
git init
git add .
git commit -m "health-skill record module: step 25 baseline"
git branch -M main
git remote add origin https://github.com/<owner>/<repo>.git
git push -u origin main
```

> 不要提交 `node_modules/`。`.gitignore` 建议包含：
> `node_modules/`、`artifacts/step22/source/`、`artifacts/step22/backup/`、`artifacts/step23/sqlite/`、`artifacts/staging-rehearsal/local/`
> 以及任何真实凭据、`.env`。

## 3. 等待并核对 CI

1. 打开仓库 **Actions** 页，点开 `record-module-ci` 最新运行。
2. 必须确认：
   - `postgres:16-alpine` service 健康检查通过；
   - `npm run check:syntax` 步骤成功；
   - `npm run test` 步骤成功，输出 `tests 128 / pass 128 / fail 0 / skipped 0`；
   - 真实集成测试 `REAL PostgreSQL: …` 出现在通过列表（不是 skip）。
3. 复制该次运行的 **run URL** 与 **commit SHA**（运行页标题右侧）。

## 4. 归档证据（复制粘贴改参数）

```bash
npm run archive:ci-record -- \
  --run-url https://github.com/<owner>/<repo>/actions/runs/<run-id> \
  --commit <40位commit-sha> \
  --tests-total 128 --tests-passed 128 \
  --node-version 22 --postgres-version 16-alpine
```

期望输出：`written: artifacts/ci/CI_PLATFORM_RECORD.json`。
归档脚本会拒绝：非 https URL、非 hex commit、未全通过计数、缺失版本信息。

## 5. 验证与交回

```bash
npm run gate:acceptance     # ci-platform-record 应变 PASS，剩余阻塞减为 4 项
npm run action:next         # 指向下一项动作
```

## 6. 常见失败处理

| 现象 | 处理 |
|---|---|
| CI 上 Node 22 与本地 Node 24 行为差异导致测试失败 | 以 CI 为准修复代码后重跑；不要修改记录掩盖失败 |
| `npm ci` 报锁文件不同步 | 本地执行 `npm install` 更新 `package-lock.json` 并提交 |
| 真实集成测试被 skip | 检查 workflow `POSTGRES_TEST_URL` 环境变量是否生效 |
| 不想公开仓库 | 可用私有仓库 + 同一 workflow；run URL 可给内部审核人访问 |
