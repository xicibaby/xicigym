# 动作卡 4｜产品 / 安全 / 运维 + 独立四方签署

**负责角色**：产品负责人、安全负责人、运维负责人、独立审批人（4 个不同的人）
**预计耗时**：30–60 分钟（可开一次 30 分钟评审会）
**产出的证据**：`artifacts/acceptance/APPROVALS.json`
**门禁角色**：第 4 项阻塞；禁止同一人担任多个角色，禁止交付作者自批。

## 1. 会前材料（提前 1 天发出）

1. 产品报告 PPT：`健康运动Skill_统一记录模块_产品报告_步骤24.pptx`
2. 步骤 24 报告：`STEP24_EXTERNAL_EVIDENCE_REPORT.md`
3. 门禁当前状态：`npm run gate:acceptance` 输出
4. 安全审查结论：`artifacts/security-baseline/HUMAN_SECURITY_REVIEW.json`
5. CI 与 staging 记录：`artifacts/ci/CI_PLATFORM_RECORD.json`、`artifacts/staging-rehearsal/STAGING_REHEARSAL_EVIDENCE.json`

## 2. 会议议程（30 分钟模板）

| 时长 | 内容 | 主讲 |
|---:|---|---|
| 5 min | 产品范围与用户价值确认 | 产品 |
| 5 min | 数据正确性、记录生命周期与用户隔离 | 研发 |
| 5 min | CI + staging 演练结果与对账结论 | 运维/研发 |
| 5 min | 安全审查结论与整改项 | 安全 |
| 5 min | 上线窗口、观察期、回滚触发条件 | 运维 |
| 5 min | 独立审批人提问与结论 | 独立审批人 |

## 3. 填写签署文件

复制模板：`行动包/审批记录模板.json` → `artifacts/acceptance/APPROVALS.json`。

要求：
- `approvals` 含 `product` / `security` / `operations` 三个角色，各自由**不同的人**填写 `name`、`title`、`signedAt`（带时区 ISO）、`decision: "approved"`。
- `independentApproval.required=true`，且 `name` 必须是**第 4 个不同的人**。
- `author.name` 填写交付作者（用于门禁检查"禁止自批"）。
- `release.commit`、`release.evidenceBundle`（含文件名与 SHA256）与发布包一致。

门禁会拒绝：占位符姓名/时间、缺角色、少于 4 个不同签署人、签署人含作者、时间无效。

## 4. 验证与交回

```bash
npm run gate:acceptance     # human-approvals 应变 PASS
npm run action:next         # 最后一项：切换门禁
```

## 5. 若有人不同意

- 记录 `decision: "rejected"` 与原因，门禁保持 BLOCKED；
- 整改后重新评审，不得修改历史签署记录；
- 独立审批人的否决优先于其他三方。
