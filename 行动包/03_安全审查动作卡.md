# 动作卡 3｜人工安全审查与签署

**负责角色**：安全负责人（主审）+ 运维负责人（联审）
**预计耗时**：1–2 小时（首次）
**产出的证据**：`artifacts/security-baseline/HUMAN_SECURITY_REVIEW.json`
**门禁角色**：第 3 项阻塞；自动化技术控制审查不等同人工审查。

## 0. 审查前先看自动化结果（5 分钟）

```bash
npm run security:baseline        # 期望 26/26 PASS，humanReviewSigned=false
npm run security:db-privileges   # 期望 21/21 PASS（需 POSTGRES_APP_URL 指向应用角色）
```

自动审查覆盖：生产配置 fail-closed、TLS `sslmode=verify-full` 强制、错误/日志脱敏、仓库密钥扫描、探针暴露默认值、锁文件、CI 加固、审批模板。
**人工审查只需核对自动审查覆盖不到的真实环境项**，逐项填下面的表。

## 1. 八个审查域（逐项打勾并写证据）

| # | 审查域 | 核对问题 | 证据/结论 |
|---:|---|---|---|
| 1 | TLS 与证书链 | 托管实例是否强制 TLS？CA/证书轮换流程？`sslmode=verify-full` 是否生效？ | ☐ 通过 ☐ 不通过 |
| 2 | 最小权限账号 | 应用账号是否无 DDL/TRUNCATE/超管？迁移账号是否独立且仅在窗口期使用？对账账号是否只读？ | ☐ 通过 ☐ 不通过 |
| 3 | 秘密管理 | `POSTGRES_URL` 等是否由秘密管理器注入？是否有轮换与泄漏处置流程？日志/镜像/仓库是否无凭据？ | ☐ 通过 ☐ 不通过 |
| 4 | 探针暴露面 | `/healthz`、`/readyz`、`/metrics` 是否仅内网/网关白名单可达？公网是否不可达？ | ☐ 通过 ☐ 不通过 |
| 5 | 日志与脱敏 | 应用日志是否不含健康数据明文、令牌、连接串？日志平台访问是否受控？ | ☐ 通过 ☐ 不通过 |
| 6 | 备份加密与保留 | 备份是否加密？访问控制、异地副本、保留期限、销毁流程是否明确并落地？ | ☐ 通过 ☐ 不通过 |
| 7 | 身份与访问控制 | OIDC issuer/audience/JWKS 是否与真实 IdP 一致？CORS 白名单、网关共享限流是否生效？ | ☐ 通过 ☐ 不通过 |
| 8 | 健康数据合规 | 数据分类、访问审计、导出与删除、保留期限是否经法务/合规确认？ | ☐ 通过 ☐ 不通过 |

## 2. 签署文件

复制模板：`行动包/安全审查记录模板.json` → `artifacts/security-baseline/HUMAN_SECURITY_REVIEW.json`，填写：

```json
{
  "humanReviewSigned": true,
  "reviewer": "<真实姓名>",
  "reviewedAt": "<ISO-8601 带时区>",
  "scope": ["tls", "least-privilege", "secrets", "probe-exposure", "logging", "backup-encryption", "access-control", "data-compliance"],
  "decision": "approved",
  "findings": [
    { "domain": "tls", "result": "pass", "evidence": "<证据链接或工单号>" },
    { "domain": "backup-encryption", "result": "pass-with-followup", "evidence": "<整改项>", "followUp": "<截止日期>" }
  ],
  "notes": "<审查范围与保留意见>"
}
```

规则：
- 只要有一项"不通过"，`humanReviewSigned` 必须为 `false`，并写整改项；不得为提高门禁而填 true。
- 签署人必须是真实安全/运维负责人，不得是交付作者本人。
- 保留意见（如"备份加密待 Q4 落地"）必须写进 `notes` 与 `findings[].followUp`。

## 3. 验证与交回

```bash
npm run gate:acceptance     # security-review 应变 PASS
npm run action:next         # 接下来是四方签署与切换门禁
```

## 4. 注意

- 本动作卡是流程模板，不构成审查结论；审查结论以签署文件为准。
- 审查发现的问题应进入整改跟踪，不因门禁变绿而关闭。
- 详细材料清单见 `docs/release/SECURITY_REVIEW_PREP.md`。
